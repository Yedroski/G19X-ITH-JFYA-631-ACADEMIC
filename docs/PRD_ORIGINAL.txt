Sistema Inteligente de Calidad de datos

	QUE ES LA CALIDAD DE DATOS??

la calidad de datos es uno de los principales problemas de las empresas es decir que los datos sean limpios,
que determina que los datos sean de calidad?? se refiere a la medida en que los datos son adecuados para su
uso previsto y como se logra esto?? cumpliendo con las siguientes caracteristicas

PRECISION:Indica qué tan fielmente los datos guardados reflejan la realidad o el valor verdadero

INTEGRIDAD: Asegura que no falte información requerida y que se mantenga las relaciones lógicas entre
las distintas tablas y sistemas

CONSISTENCIA:no varian los formatos entre registros por ejemplo formatos diferentes de fechas entre
registros o tablas

FIABILIDAD: grado de confianza, un dato es fiable si su origen es conocido y verificable, proviene de una fuente 
autorizada y se procesó mediante reglas de negocio estables y auditables

Actualidad de datos: depende que tan oportunos son los datos en relación con el momoento en que se necesitan para 
operar o tomar decisiones es decir, refleja el estado presente del fenómeno que se está midiendo 

	PROPOSITO 
el propósito de la calidad de datos es asegurar que los dato de una organiación sean confiables y adecuados para el 
uso que se les quiere dar (como ya se vio en la defincion de calidad de datos) entonce la calidad de datos busca que 
una empresa pueda confiar en su información, para operar y tomar decisiones. Datos de mala calidad pueden provocar reportes
incorrectos, decisiones equivocadas, errores en procesos, duplicación de trabajo y problemas en análisis posteriores

	ALCANCE

El sistema permitirá evaluar la calidad de un archivo de datos tabular, inicialmente en formato CSV, 
mediante un proceso automatizado de perfilado y validación

	FLUJO DEL SISTEMA

DATOS SINTÉTICOS -> INGESTA -> PERFILADO -> MOTOR DE REGLAS -> 
(valores faltantes, duplicados, formatos, consistencia, integridad anomalías)
->Quality Score -> (Recomendaciones, historial, incidencias) -> Dashboard ejecutivo

| Métrica | Qué mide | Fórmula sugerida |
|---|---|---|
| **Completitud** | Qué porcentaje de datos obligatorios está presente | `(campos no nulos / campos evaluados) × 100` |
| **Validez** | Qué porcentaje cumple las reglas definidas | `(registros válidos / registros evaluados) × 100` |
| **Unicidad** | Qué porcentaje de registros no está duplicado | `(registros únicos / registros totales) × 100` |
| **Consistencia** | Qué porcentaje no presenta contradicciones entre campos | `(registros consistentes / registros evaluados) × 100` |
| **Exactitud** | Qué porcentaje de datos coincide con una fuente o valor esperado | `(datos correctos / datos verificados) × 100` |
| **Quality Score** | Indicador global de calidad | Promedio ponderado de las métricas anteriores |

Quality Score
Esta debería ser la métrica principal de tu sistema.
Puedes combinar las diferentes dimensiones.
Para el MVP se utilizara:

\[
QualityScore =
0.30C +
0.30V +
0.20U +
0.20I
\]
donde:
- C: Completitud
- V: Validez
- U: Unicidad
- I: Consistencia


Indicadores adicionales útiles
Además de las métricas porcentuales, tu dashboard debería mostrar algunos KPIs operativos:
- Total de registros analizados.
- Total de columnas.
- Total de valores nulos.
- Total de registros duplicados.
- Total de reglas ejecutadas.
- Total de reglas incumplidas.
- Total de registros con errores.
- Porcentaje de registros con al menos un problema.
- Número de anomalías detectadas.
- Tiempo total de análisis.


RESTRICCIONES:

| ID | Restricción | Descripción |
|---|---|---|
| R-02 | **Alcance limitado** | El sistema se enfocará en análisis básico de calidad de datos: completitud, validez, unicidad, consistencia y cálculo del Quality Score. |
| R-03 | **Fuente de datos limitada** | En la primera versión, el sistema procesará principalmente archivos **CSV**, dejando integraciones con bases de datos o APIs para versiones futuras. |
| R-04 | **Procesamiento batch** | El análisis se realizará bajo demanda sobre archivos cargados por el usuario. No se implementará procesamiento en tiempo real ni streaming. |
| R-05 | **Volumen de datos** | El MVP estará orientado a datasets pequeños y medianos, con un límite objetivo cercano a **100,000 registros**, sujeto a los recursos disponibles. |
| R-06 | **Recursos computacionales** | El rendimiento dependerá de la capacidad del equipo o servidor donde se ejecute la aplicación. No se utilizará infraestructura distribuida. |
| R-07 | **Reglas de calidad limitadas** | Se implementará un conjunto reducido de reglas configurables, como campos obligatorios, rangos, formatos, valores permitidos y unicidad. |
| R-08 | **Exactitud limitada** | El sistema no podrá determinar automáticamente si un dato representa correctamente la realidad cuando no exista una fuente externa de referencia. |
| R-09 | **Detección de anomalías básica** | En caso de implementarse, la detección de anomalías utilizará métodos estadísticos simples y no modelos avanzados de Machine Learning. |
| R-10 | **Sin corrección automática** | El sistema identificará problemas y podrá sugerir acciones, pero no modificará automáticamente los datos originales. |
| R-11 | **Interfaz simplificada** | El dashboard tendrá únicamente las vistas necesarias para mostrar métricas, errores y resultados principales del análisis. |
| R-12 | **Seguridad básica** | El MVP no incluirá mecanismos avanzados como SSO, MFA, gestión compleja de roles o integración con sistemas corporativos de identidad. |
| R-13 | **Usuarios limitados** | La primera versión no estará diseñada para una gran cantidad de usuarios concurrentes. |
| R-14 | **Persistencia limitada** | El histórico de análisis será básico o podrá omitirse si el tiempo de desarrollo no permite completar esta funcionalidad. |
| R-15 | **Compatibilidad de datos** | El sistema estará enfocado principalmente en datos tabulares estructurados. No se analizarán imágenes, audio, video ni documentos no estructurados. |
| R-16 | **Dependencia de reglas de negocio** | Algunas validaciones requerirán reglas definidas previamente por usuarios de negocio, Data Stewards o responsables de los datos. |
